### Learned

- **`0` and `NaN` must be semantically distinct.** `0` is an instruction ("go flat");
  `NaN` is silence ("hold current state"). `BuyAndHold` must emit `[1, NaN, NaN, …]`,
  not `[1, 0, 0, …]`. The engine diffs `current != prev` for order generation, so a
  `0` after `NaN` (never-seen state) is a no-op, but `0` after a long `1` schedules a
  sell. This distinction needs to be in both the spec and the `generate_signals` docstring.

- **Force-closing pending buys on the last bar is the right call.** Executing the buy
  then immediately force-closing at the same open is economically meaningless (net-zero
  position change, double cost) and pollutes the trade ledger. `pending_orders.clear()`
  before the force-close loop eliminates an entire class of end-of-backtest artefacts.

### Learned

- **The complete-artifact design (D10) relocates extensibility, not removes it.**
  Making `BacktestResult` complete enough (equity curve + trade ledger + daily positions
  + cost totals) means every downstream report is a pure function over the artifact —
  adding a metric never touches the engine. Same extensibility as backtrader's in-loop
  analyzers, different placement.

- **`WalkForwardSplit` belongs in Phase 3, not Phase 6.** Building the iterator now
  costs eight lines of logic and gives Phase 6 a tested interface. Adding it post-hoc
  would require changing the Phase 3 public API, which is a breaking change for anything
  Phase 4/5 has already imported.

## Saturday Retrospective — 2026-W23

Spec finalization week. The main output is PHASE_3.md and the CLAUDE.md update — ready
to commit at the start of W24.

The most time-consuming section was lookahead safety (§7): getting the three-layer model
(indicator causality / strategy causality / execution timing) stated precisely enough to
serve as a code-review reference. Worth doing carefully — a vague spec produces vague
code, and lookahead safety is the one property where vagueness is unrecoverable.

The `0` vs `NaN` signal distinction will be the most common strategy-author mistake
encountered in Phase 4. It is now documented in both the spec and the ADR, and the
`BuyAndHold` reference implementation will be the canonical example of getting it right.

### Learned

- **`min_periods=window` (not 1) is the correct default for indicators.** pandas defaults
  `min_periods` to 1 for `rolling().mean()`, returning a partial-window value from bar 1.
  Setting `min_periods=window` enforces the warmup contract: NaN until `window` bars are
  available. The engine treats NaN signals as "no opinion"; indicators should have the
  same contract.

- **RSI Wilder smoothing uses `alpha = 1/window` (not the standard EMA `2/(window+1)`),
  equivalent to `com = window - 1` in pandas.** Using the wrong alpha produces RSI values
  bounded in [0, 100] — passing sanity checks — but diverging from charting-platform
  references by 1–3 points. The `adjust=False` convention also differs from pandas EMA
  default; both details matter for reproducibility.

- **`BuyAndHold` initially used `pd.Series(0, ...)` for non-entry bars.** `0` is a "go
  flat" instruction; `NaN` is "hold". A `BuyAndHold` emitting `[1, 0, 0, …]` enters at
  bar 0 and sells at bar 2 because the engine reads a long→flat transition at bar 1.
  Fixed before step 5: all-NaN Series with `iloc[0] = 1`. The engine behavioral tests
  later confirmed this correction was necessary.

### Learned

- **The buy-sizing test was the most revealing test in the suite.** `test_buy_sizing_floor_
  of_equity_times_max_pct` was initially written assuming fill-price sizing (999 shares)
  but the engine uses open-price sizing (1000 shares). This was not a bug — it was an
  undocumented design choice that the test surfaced. Well-written behavioral tests reveal
  assumptions, not just verify behaviour.

- **ruff's E501 check requires structurally breaking long keyword-argument calls.** Four-
  argument `portfolio.buy(...)` calls exceed the 100-char limit when written inline; ruff-
  format rewrites them to multi-line automatically. The pre-commit hook caught and fixed
  them; lesson is to let the formatter run before manually adjusting layout.

- **Clearing `pending_orders` before the force-close loop is critical.** If a buy is
  pending for the last bar and force-close runs first, the loop sees no positions. The
  `pending_orders.clear()` must precede the sell loop — the spec says so, but it is the
  kind of ordering detail that is easy to reverse when writing the loop from scratch.

### Learned

- **Boolean signal fragility makes small scramble windows unreliable for detection
  tests.** `_LookaheadStrategy` uses `close.shift(-1) > close` — a boolean comparison.
  Even when the shuffled value at `T+1` is different, the direction relative to `close[T]`
  may not flip, so the signal stays the same and no `LookaheadError` is raised. This only
  bites with small windows (e.g. `perturbation_start=-20`) where only one bar in the safe
  zone depends on scrambled data; the default `-50` window is large enough that some
  boolean flip is virtually guaranteed.

- **"No false positives on causal" is an unconditional guarantee; "catches this lookahead"
  is probabilistic.** A causal strategy's past signals are mathematically independent of
  future data — no permutation can change them. Testing that property holds regardless of
  the random seed or window size. Testing that a boolean lookahead strategy is caught
  depends on specific float values produced by a particular permutation. For the custom-
  parameter test, the unconditional property is the right thing to test; the main detection
  tests (`test_catches_shift_minus_one_lookahead`, `test_lookahead_error_names_perturbation_
  index`) still verify that the audit does catch lookahead with the default window.

- **Trigger-based vs state-based signal idioms are both valid but suit different strategy
  shapes.** `BuyAndHold` emits non-NaN only on position changes (trigger); `SmaCrossover`
  emits dense 0/1 on every post-warmup bar (state). The engine handles both identically
  because it acts only on transitions. Key rule: always emit NaN explicitly during warmup —
  using 0 as a proxy is a silent bug if a prior position is open (triggers a spurious sell).

- **`from tests.backtest.conftest import make_synthetic_bars` fails without
  `pythonpath = ["."]`.** pytest auto-loads conftest for fixture injection but does not add
  `tests/` to `sys.path`. Plain helper functions in conftest are not importable unless the
  project root is on the path. Revertible: remove the pyproject line and inline a local
  helper instead.

- **`itertuples()` stubs return `Iterable[Any]`; attribute access on `Any` rows produces
  Pylance warnings even after casting.** The warning is on the attribute access itself
  (`row.fill_price`), not on downstream operations. Fix: extract typed numpy arrays with
  `.to_numpy()` before the loop and index into them — no `Any` in sight.

- **`Trade.total_cost` is commission + tax only; slippage is embedded in `fill_price`.**
  Summing `trades["total_cost"]` for a "total fees" metric silently omits slippage costs.
  The correct source is `result.total_commission + result.total_tax +
  result.total_slippage_cost`, which the engine pre-aggregates and stores separately.

- **Bitwise `&` has higher precedence than `>` in Python.** `len(a) > 0 & len(b) > 0`
  parses as `len(a) > (0 & len(b)) > 0`, which simplifies to `len(a) > 0 > 0` — always
  `False`. The fix is `len(a) > 0 and len(b) > 0`. This silently made `win_loss_ratio`
  always `nan`; caught by code review, not by a test (the test checked NaN for the
  empty-trades case, which is correct regardless of the bug).

- **`_round_trips` assumes whole-position FIFO and is only correct for Phase 3's
  constraint set.** It pairs the i-th buy with the i-th sell per ticker after sorting by
  timestamp. This is exact when: (1) the engine only enters full positions (no partial
  fills), (2) only long positions are allowed (`allow_short=False`), and (3) position
  sizing is all-or-nothing per bar. When Phase 5 introduces partial fills or Phase 6
  allows short positions, `_round_trips` will need to be replaced with a proper FIFO
  queue that tracks remaining shares per lot. For now the limitation is harmless, but
  worth flagging before Phase 5 extends the engine.

### Learned

- **`relativedelta.years` counts only complete years, which is the correct validation
  unit.** `relativedelta(date(2023, 6, 1), date(2020, 1, 1)).years` returns `3` (not 3.4),
  so a `train_years=3, test_years=1` config on a 3.9-year range correctly raises — the
  test window wouldn't be a full year. Using `.days` would require a calendar-aware
  trading-day count; `.years` is the right granularity for a calendar-year iterator.

- **The SMA(20)/60 crossover on TSMC generates very few trades — 1–3 per year.**
  5 walk-forward folds showed 1, 3, 2, 3, 2 trades respectively. Low turnover means the
  0.585% per-round-trip cost floor is not the dominant drag; the signal simply doesn't
  predict direction reliably out-of-sample. Only 2 of 5 folds were positive (2020 Covid
  recovery at +7.91%, 2024 at +2.95%). The 2022 bear market fold was worst (−1.49%).

- **Walk-forward stability ≠ walk-forward profitability.** The report was designed to test
  whether the strategy's behaviour is consistent across time — not whether it generates
  alpha. A strategy with a Sharpe ranging from −1.5 to +2.8 across folds is telling you
  the signal is weak, not that the backtester is broken. This is the exact insight the
  report is meant to surface before Phase 4 parameter searches start.

## Retrospective

**Goal:** Phase 3 build steps 0–17. All steps complete; phase closed.

**Went well:**
- Front-loading steps 0–1 (references writeup + ADR) before any code paid off; no
  mid-step interface redesigns
- Steps 9–14 (audit through stability report) shipped in a single session — the spec was
  tight enough that each step had exactly one thing to build
- `BacktestResult` as a complete immutable artifact (D10) absorbed every new metric
  request without reopening the engine; this design decision already proved its value
  within the same phase

**Slipped:**
- `BuyAndHold` 0-vs-NaN bug caught during engine test writing, not during strategy
  implementation — a one-commit fix, but it should have been right the first time given
  the spec's explicit signal-semantics section
- Bitwise `&` precedence bug in `win_loss_ratio` was caught by code review, not by a test;
  the test covered the NaN case but not the non-empty case where the bug was silent

**Surprises:**
- The buy-sizing behavioral test uncovered an undocumented design decision (open-price
  sizing vs fill-price sizing); well-written behavioral tests reveal assumptions, not just
  verify behavior
- `pythonpath = ["."]` in `pyproject.toml` was needed for conftest helper imports; one
  line, but not in any Phase 3 spec checklist

**Decisions to carry into Phase 4:**
- `_round_trips` in tearsheet.py is a Phase 5 blocker for partial fills; flag when
  starting Phase 5
- The 0-vs-NaN footgun will be the most common Phase 4 strategy-author mistake; consider
  an engine-level warning when a strategy emits 0 on bar 0 before any position is open
- The 0.3% sell tax will kill any high-turnover strategy in Phase 4; scrutinize costs
  before claiming alpha

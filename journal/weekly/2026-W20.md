  tested with hand-made DataFrames

### Learned
- **Atomic write pattern for Parquet:** write to `{ticker}.parquet.tmp`, then
  `Path.rename()`. Prevents a corrupt read if the process dies mid-write.
- **Merge semantics on write:** read existing → `pd.concat` → `drop_duplicates(
  ['ticker','date'], keep='last')` → sort by date → write. Never blindly append.
  The `keep='last'` policy means a re-fetch always wins over stale stored data,
  which is the right behaviour for a backfill-and-refresh workflow.
- **`read_ohlcv` must return an empty DataFrame with the correct schema if the
  file doesn't exist**, not raise `FileNotFoundError`. Callers expect to check
  `len(df)`, not catch exceptions.

### Learned
- **VCR gotcha: `vcr_config` fixture overrides `--record-mode` CLI flag.** Never
  set `record_mode` inside the `vcr_config` fixture — it silently wins over the CLI
  flag and prevents re-recording. Instead: set `addopts = "--record-mode=none"` in
  `pyproject.toml`; override on CLI with `--record-mode=rewrite` when needed.
- **`@pytest.mark.vcr("name.yaml")` is not supported in pytest-recording 0.13.4.**
  Cassettes are auto-named from the test function name. Do not try to pass a custom
  cassette name as a marker argument.
- **`load_dotenv()` order matters in the VCR test fixture.** The `source` fixture
  must call `load_dotenv()` before checking `os.getenv("FINMIND_TOKEN")`. If
  `monkeypatch.setenv` is called first, the fake token overwrites any real token
  subsequently loaded from `.env`, which means cassette recording goes out with
  `"test-token"` and returns 400 responses. The correct pattern:
  `load_dotenv()` → check if token exists → only then `monkeypatch` if absent.
- **`pd.concat` downcasts typed columns when one input is an all-object empty
  DataFrame.** Concat'ing a properly-typed DataFrame (e.g. `datetime64[ns]` column)
  with `pd.DataFrame(columns=[...])` (all object dtype) downcasts the typed column
  to `object`, causing downstream pandera schema failures. Fix: use a `parts` list
  pattern — only concat non-empty DataFrames, and skip the concat entirely if only
  one DataFrame has data.
- **`list_universe` filter needs three conditions, not two.** Type `"twse"` alone
  does not exclude ETFs (0050 is type `twse` with `industry_category == "ETF"`).
  ETF exclusion via `industry_category != "ETF"` alone does not exclude REITs
  (e.g. `01007T`). All three conditions are required: `type == "twse"` AND
  `industry_category != "ETF"` AND `stock_id.str.match(r"^\d{4}$")`.
- **FinMind has corrupted data rows for some tickers (e.g. 6770: `open > high`).**
  This is caught by our OHLCV schema cross-field checks, which is correct behaviour.
  Root cause is bad source data, not unadjusted prices — intraday prices (`open`,
  `high`, `low`, `close`) describe the same session; no corporate-action adjustment
  would cause `open > high` within a single day. Resolution belongs in `quality.py`
  (Step 9: log/flag rather than silently drop or crash); for now, the schema rejects
  bad data at the boundary as designed.
- **VCR cassettes are committed to make tests reproducible without a token or
  network.** Anyone who clones the repo can run `uv run pytest` and cassette tests
  replay offline. The `Authorization` header is filtered from cassette files so the
  token is never stored on disk.
- **`end` parameter in `get_corporate_actions` is unused.** FinMind's
  `TaiwanStockDividendResult` and `TaiwanStockCapitalReductionReferencePrice`
  endpoints do not accept an `end_date` filter. The parameter cannot be removed
  because it is in the `DataSource` ABC. Three options deferred for later decision:
  post-fetch filter in the adapter, document as advisory in the docstring, or make
  `end` optional in the ABC.

### Learned (continued)
- **TWSE `STOCK_DAY` is monthly-granularity.** You must loop month-by-month and
  stitch results; there is no single-call date-range endpoint. Per-month `NoDataError`
  is swallowed and only raised when the full requested range returns nothing.
- **ROC date conversion:** TWSE returns dates as `"1120601"` (民國 112, month 06,
  day 01). Conversion: Gregorian year = ROC year + 1911.
- **Suspended trading days arrive as `"--"` strings**, not null. Must be dropped
  before dtype conversion; converting `"--"` to float raises silently and produces `NaN`.
- **DuckDB glob view creation must be conditional.** `read_parquet('dir/*.parquet')`
  errors if no files match. Check `any(dir.glob("*.parquet"))` before registering each view.
- **`union_by_name=true` is required** in DuckDB `read_parquet` when the optional
  `value` or `fetched_at` columns may be absent from older files.

### Learned
- **Mutable default `date.today()` in a function signature is evaluated once at import
  time.** Use `None` as the default and resolve inside the function body. This is doubly
  important when `lru_cache` is involved — the stale default would become part of the
  cache key.
- **`lru_cache` requires all arguments to be hashable.** The cleanest pattern is a
  private cached function that only receives already-normalized, hashable inputs
  (`str`, `date`), with the public function handling normalization before delegating.
- **`autouse=True` cache-clear fixture is essential for unit tests that mock storage.**
  Without it, a mock return value from one test is served from the LRU cache in the
  next test, causing false positives or false negatives depending on test order.
- **Anchor tests skip via a module-scoped fixture, not a mark.** The fixture calls
  `get_ticker_date_range("2330")` and issues `pytest.skip()` if it returns `None`.
  All parametrized anchor tests depend on this fixture and inherit the skip automatically.
  This is cleaner than per-test skip guards because the skip condition is evaluated once.

### Learned
- **`權息` is a combined cash+stock dividend event.** `TaiwanStockDividendResult`
  has three `stock_or_cache_dividend` values, not two: `息` (cash), `權` (stock),
  `權息` (combined). For back-adjustment, mapping `權息` → `cash_dividend` is
  mathematically correct because `stock_and_cache_dividend` equals the full price
  deduction in all cases (`before_price - amount ≈ after_price`), regardless of
  whether the payout was paid as cash, stock, or a mix.
- **FinMind encodes previous day's average price as `open` for TPEx-period rows.**
  TPEx has no opening call auction, so there is no true `open` price. FinMind fills
  the field with the previous day's reference average. This causes `open > high` on
  gap-down days, breaking the OHLCV schema invariant. The violation occurs exclusively
  before each ticker's TWSE listing date — confirmed by checking Yahoo Finance for all
  three affected tickers (6669, 7769, 6919). Clamping `open` to `[low, high]` is the
  temporary workaround; the proper fix (restrict to TWSE listing date) is FU-05.
- **`pd.DataFrame(columns=[...])` produces all-object dtype columns.** An empty
  DataFrame constructed with a column list has `object` dtype for every column,
  including ones that should be `datetime64[ns]`. Pandera sees this as a type
  violation. Fix: construct empty DataFrames using `pd.Series(dtype=...)` per column,
  or add a `df.empty` guard before schema validation in the writer.
- **Backfill skip condition never fires when `--end` defaults to today.** Stored data
  ends at yesterday's close (market hasn't closed today yet), so `stored_end` is always
  one day behind `requested_end`. The full 10-year range is re-fetched every run, relying
  on `write_ohlcv`'s dedup merge for idempotency. Correct but wasteful; deferred as FU-04.
- **Root cause research before fixing saves time.** The `open > high` issue was initially
  ambiguous (TWSE call auction vs continuous session split? data corruption?). Examining
  TPEx CSV data and Yahoo Finance confirmed the TPEx-period root cause definitively,
  which steered toward the right fix (restrict by listing date, not drop by rule).

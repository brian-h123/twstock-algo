### Learned

- **Routing every state change through one `_emit` helper is what
  guarantees the simulator's internal account mirror and the drained event
  stream can't diverge.** Two independent code paths writing to the
  account and to the event log separately would only need one missed call
  site to desynchronize them — collapsing to a single emission point makes
  that class of bug structurally unavailable rather than something code
  review has to keep catching.
- **A duplicate-`order_id` guard needs to check account history, not the
  working-order set.** A resolved order has already left the working-order
  set by definition, so checking only that set would let a duplicate
  `order_id` slip through once the original order settles — the guard has
  to consult the same place `fold()` would find the original.

## Retrospective

### What went well

- **`process_bar`'s single-`_emit` design paid for itself immediately.**
  Composing `classify_missing_bar`, the price-limit provider, and the fill
  model into one `_resolve_order` decision point, with one emission path
  out, kept the whole orchestration step to one session despite touching
  nearly every module built in W27–W28.

### What to carry forward

- Both future-work items flagged this week (wall-clock provenance,
  allocator unification) are intentionally deferred to their natural
  triggers (Phase 8 kickoff; the ADR 0008 backtester migration) rather than
  solved speculatively now — recorded in `journal/phase_8_backlog.md` so
  they aren't silently forgotten in the meantime.

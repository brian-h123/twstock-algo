### Learned

- **`TaiwanStockDividendResult.stock_and_cache_dividend` is `before_price −
  reference_price`, not the sum of payout amounts.** For a combined event with D=1.0
  NT$ cash and a 10% stock dividend, the face-amount sum is 2.0 NT$ but the market
  deduction is 4.69 NT$. The `Result` dataset is useful for cross-checking reference
  prices but is the wrong source for ingestion — it obscures the cash/stock breakdown
  needed for correct per-leg back-adjustment.

- **`date` in `TaiwanStockDividend` is the record date (權利分派基準日), not the
  ex-date.** Per-leg ex-date columns (`CashExDividendTradingDate`,
  `StockExDividendTradingDate`) must be used. Using `date` as the ex-date would shift
  all adjustments by roughly one month.

- **`CashIncreaseSubscriptionRate` is the post-carve-out subscription rate, not total
  dilution.** After 公司法 §267 employee and underwriter allocation, the rate shown is
  the existing-shareholder entitlement — a subset of total issuance. Dilution must be
  derived from share counts: `TotalNumberOfCashCapitalIncrease /
  ParticipateDistributionOfTotalShares`.

- **Capital reduction ratio direction: pre-event prices scale UP, not down.**
  `PostReductionReferencePrice / ClosingPriceonTheLastTradingDay > 1` because shares
  are worth more after reduction (fewer shares, same underlying assets). Applying
  `1/ratio` would deflate pre-event history instead of inflating it. The factor is
  `ratio` directly.

- **Latent multi-ticker fixture bug:** A module-scoped TSMC-only fixture (`adj_2330`)
  used for parametrized tests that now include 1101 events would silently compare 1101
  ex-dates against TSMC adjusted history. The test would pass or fail based on random
  TSMC price movements near the 1101 event date — not a correctness signal. Fix: each
  parametrized anchor test loads its own ticker's data inline using the ticker from the
  anchor, not from a hardcoded fixture.

- **Backfilling a non-universe ticker for test purposes is valid.** The storage layer
  is ticker-agnostic. `data/` is gitignored. 1101 data sits in
  `data/by_ticker/1101.parquet` as test infrastructure without entering `universe.py`
  or `config.py`.

- **`stock_and_cache_dividend` cross-validator check must use the TWSE formula, not
  raw amounts.** `expected_sacd = before_price − expected_ref` (derived from the
  reference-price formula) gives the correct expected deduction. Computing it as
  `cash_total + stock_face_total` is wrong for any event with a stock leg, because
  the stock leg is valued at market price in the deduction, not face value.

  `PostReductionReferencePrice / ClosingPriceonTheLastTradingDay`. Regenerated
  `tests/fixtures/anchor_dividends.json`.

  all 9 anchor tests green. Full suite: 129 passed, 6 skipped. Both FU-02 and FU-06

### Learned

- **`write_corporate_actions` merge semantics create a Parquet retention hazard.**
  The merge deduplicates by `(ticker, ex_date, action_type)` — it can add and update
  rows but cannot delete them. A row written under an old ex_date (e.g. the suspension-
  start date) will persist in Parquet even after the source is fixed not to emit it.
  Purge requires deleting the file and re-backfilling from scratch.

- **FinMind's `ClosingPriceonTheLastTradingDay` is not the actual last traded price.**
  For Yageo 2022 the field reports 400 while the actual market close was 268. Both the
  closing price and `PostReductionReferencePrice` are at the same reporting scale, so
  their ratio (≈ 1.247) is still the correct price-jump factor. A data-display quirk,
  not a calculation error.

- **Wealth-continuity is an approximation, not an identity.** For capital reduction,
  `X ≈ R×Y + C` holds when the market closes at the TWSE reference price on ex-date,
  but intraday trading can push the actual close (Y) away from the reference. The formula
  `(X - C) / (R × Y)` avoids this assumption entirely and always matches the
  adjustment applied by `adjust()`.

- **`cash_amount = NaN` for capital_reduction is intentional.** The entire price
  adjustment is captured in the `ratio` column (the price-jump factor
  `PostRef / ClosingLast`). `adjust()` never reads `cash_amount` for this action type,
  so NaN is harmless; there is no separate cash component to track.

### Learned

- **`st.session_state` clamping must happen before the keyed widget is rendered.**
  Streamlit reads `session_state[key]` first when rendering a keyed widget, ignoring
  the `value=` argument on all reruns after the first. Mutating the state dict before
  the `st.date_input` call is what causes the input to show the clamped value on ticker
  switch — not after.

- **The selectbox returns the display label string, not the ticker.** `split(" — ")[0]`
  is required to recover the 4-digit ticker before passing to any loader or
  `get_available_range`. Passing the full label silently produces empty DataFrames.

### Learned

- **`st.plotly_chart(use_container_width=True)` is required.** Without it the figure
  renders at a fixed default width inside a wider container, leaving empty horizontal
  space. Not a Plotly issue — a Streamlit layout default that applies to all chart types.

  pattern prevents both the Streamlit conflict warning and the clamp from overwriting
  a value the user has already set in the current session. The spec described this
  correctly; it just needed to be applied literally.
